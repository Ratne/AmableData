# Anonymous usage statistics

amable is free and open source. To know whether people actually use it, and which parts,
every installation sends **one small anonymous ping a day** with structural counts. It
helps decide what to build next, and whether the project is worth continuing.

It is on by default and you can switch it off at any time, without losing anything.

## What is sent

`POST https://app.amabledata.com/v1/public/telemetry`, once every 24 hours, about 500 bytes:

```json
{
  "anonymousId": "6f1c1f4e-0f0a-4b52-9d43-1f6a2b0c9e11",
  "version": "2026.11.25",
  "schemaVersion": 31,
  "edition": "open_source",
  "counts": {
    "tenants": 2,
    "users": 5,
    "sites": 1,
    "funnels": 3,
    "forms": 7,
    "pages": 4,
    "automations": 6,
    "products": 12,
    "bookingCalendars": 1
  },
  "contactsBucket": "1k-10k",
  "apps": ["mapbox"]
}
```

| Field            | Meaning                                                                                          |
| ---------------- | ------------------------------------------------------------------------------------------------ |
| `anonymousId`    | Random UUID generated by the installation. A new one is generated every time you switch it back on |
| `version`        | Release of the running code                                                                      |
| `schemaVersion`  | Database schema version                                                                          |
| `edition`        | `open_source`, `self_hosted_licensed` (linked to a cloud account) or `managed` (amabledata Cloud) |
| `counts`         | Number of workspaces, users, tracking sites, active funnels, forms, landing pages, automations, products and booking calendars, summed over all workspaces |
| `contactsBucket` | Total contacts as a range only: `0`, `1-100`, `101-1k`, `1k-10k`, `10k+`                          |
| `apps`           | Ids of the public catalog apps that are active in at least one workspace                         |

The exact body of the next ping is shown in **Settings > Operations > Anonymous usage
statistics > Show the exact data**, before anything is sent.

## What is never sent

No names, emails, domains, hostnames, workspace names or slugs, no contact, visitor or
form data, no license key, no account id. The ping is not authenticated: even cloud
installations send it without their license key, so it cannot be tied to a customer.

On the receiving side the IP address is not stored (only the country Cloudflare derives
from it), and `anonymousId` is stored only as a salted SHA-256 hash. Pings are kept
400 days and only aggregate charts are looked at.

This is separate from the visitor tracking amable offers to its users: that data stays in
your installation and never reaches the telemetry.

## How to switch it off

- **In the app**: Settings > Operations > Anonymous usage statistics (workspace owners).
  Switching it off stops the pings immediately and forgets the anonymous id.
- **Self-hosted setup**: `pnpm self-host:setup --deploy --no-telemetry` (or
  `--telemetry off`). The script asks once on a terminal and keeps the answer.
- **Any deployment**: set the variable `TELEMETRY=off` on the core worker. It cannot be
  switched back on from the app.
- **amabledata Cloud**: the checkbox when you create the installation, then the
  toggle on the installation page of the portal at any time.

Development builds (no release version) never send anything.

The code is in `apps/core/src/platform/usage-telemetry.ts`.
